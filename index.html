Data work

Flood risk at rural airports

Modeling flooding and drainage mitigation at Jasper County Airport, a general aviation field in Rensselaer, Indiana.

ArcGIS StoryMap · Gavin Ho Rainfall and Runways A Deep Dive into Flood Risks at Rural Airports Read the story ↗
ArcGIS Pro 3.3 · Flood simulation Sep — Dec 2024

Rural airports rarely have advanced drainage, and even 3 mm of standing water can cause aquaplaning. I simulated historical and record rainfall events on a 2.5 m terrain model to find where water collects on runways, taxiways and aprons. I then designed and tested drainage mitigation directly in the DEM.

Risks identified

  • Runway hydroplaning
  • Taxiway traction loss
  • Fuel station contamination
  • Grass runway softening
  • Hangar & apron access
  • Emergency road access

Approach

  1. 01Baseline model of a real 2018 storm (2.67 in over 1.5 hr) from NOAA records
  2. 02Time-series and back-to-back rainfall runs, using each depth raster as the next baseline
  3. 03SSURGO soil infiltration (clay loam vs. sandy loam) folded into the model
  4. 04A reusable ModelBuilder tool for drainage-line delineation, validated against Indiana's record 2.7 in/hr event
  5. 05Proposed 12 m drainage ditches carved into the DEM with Euclidean Distance to redirect flow

AI workflow

AI-assisted development

I use AI coding agents as part of my engineering process. The agent works from a written spec and connects to the tools I already use through the Model Context Protocol. I review every change. This is how I ship planning tools quickly without handing client data to a model.

  1. SPECDefinePRD, data schema and design system written first as agent context
  2. MCPConnectAgent reaches GitHub, Figma and document stores through MCP servers
  3. AGTBuildClaude Code implements, runs self-tests and renders previews
  4. QAReviewHuman review, headless browser checks and version control before release
